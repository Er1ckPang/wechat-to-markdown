第一阶段：手动保存

  1. 打开 wx2md-local-v1.3.0.p 中的 local-archive 目录；Windows 双击 启动工具.cmd，Mac 按下方安装指南操作。当前电脑已经安装了依赖，会直接启动。
  2. 浏览器会打开 http://127.0.0.1:17880。若浏览器没有自动打开，手动访问这个地址。
  3. 在“手动保存”粘贴公众号、知乎、CSDN、博客园等文章链接，点击 保存文章。可以粘贴多条链接，也可以粘贴包含链接的文字消息；每次最多 100 篇。
  4. 在“保存记录”页等对应记录显示 保存完成，点击 MD 文件、内嵌 HTML、手机长图、电脑长图 查看保存结果，或点击 打开文件夹 查看全部文件。
  5. 需要改变保存位置时，打开“保存设置”，修改 保存目录。默认目录是工具目录下的 archives。

关闭操作页面后，后台仍在运行。再次双击启动文件会重新打开同一个页面。需要停止时，点击 保存设置 → 停止本地工具；正在处理的文章完成后才允许停止。

文章链接从哪里获取

在微信打开文章，使用右上角菜单的“复制链接”，粘贴到工具页面。链接形如 https://mp.weixin.qq.com/s/…。保留完整链接，不要自行删除查询参数。

手机与电脑长图

每篇分别使用 432 × 768 的手机窗口（9:16） 和 1280 × 720 的电脑窗口（16:9） 重新排版。这里的比例是浏览器阅读窗口比例；保存的是整篇文章，最终长图高度取决于正文长度。电脑保留选中正文文章栏宽度，再裁掉栏外多余空白；宽表格在对应文章宽度内换行，所有列保留，避免为了表格增加整张图的右侧空白。内嵌 HTML 仍保留原网页样式，表格可按原方式滚动。

截图清晰度

默认按 3 倍设备像素 逐屏采集，按实际滚动位置裁剪重叠，验证每处接缝后无损编码为 PNG。两种长图各保存一张，不再生成分段文件。采集像素不会再次缩放；文字清晰度与源图细节分别由渲染分辨率和源图片决定。设置可选 1、2、3 或 4 倍。点击“手机长图”或“电脑长图”，选择 100% 像素 可看细节；阅读页面由服务临时生成，不写入文章目录。超过单张 50 万像素行或页面无法可靠排版时，任务会明确失败，不生成冒充完整的长图。

批量、并发与失效提醒

每次最多 100 个不同链接；手动、消息模拟与飞书使用同一上限。任务先写入本地队列。“保存设置”可选择并发 1–4 篇，默认 2 篇；同网站最多 2 篇，长图逐篇生成。网站限流时暂停该站点的新任务约 60 秒，其他站点继续。已开始的任务不会因调低并发被中断。

删除、过期、下架及 HTTP 404／410 显示“链接已失效”，页面汇总提醒。公众号迁移自动跟随微信提供的“访问文章”链接，记录原始与新地址，最多 5 次并检查循环；新文章需要验证时，记录提供单篇验证按钮和普通浏览器导入入口。验证码或 HTTP 403／429 不表示文章永久失效。

重新保存

同一篇文章会自动去重。需要刷新归档或重试缺图时，点击记录中的 重新保存，会生成新的目录，之前的文件仍保留。

“去验证”一直超时：从普通浏览器导入

先在日常使用的 Edge / Chrome 中正常打开文章，确认正文可见后再保存。工具导入已经保存的网页，不需要再次访问微信验证服务。

  1. 迁移文章先点击记录中的“新文章”链接，在日常浏览器中正常打开。
  2. 滚动到正文底部，等待图片加载。Windows 可尝试 Ctrl+S，在保存类型中选择“网页，单个文件”（MHTML）。Mac 没有该选项时，使用 SingleFile 扩展保存内嵌 HTML。
  3. 回到首页“手动保存”，展开“采集浏览器验证超时？从普通浏览器导入”。填写实际保存的文章链接，迁移文章填新链接。
  4. 选择一个 .mhtml / .mht / .html / .htm 文件（最多64 MB），点击“导入并生成归档”。也可以从失败记录的“从普通浏览器导入”入口进入，继续原任务并保留迁移信息。
  5. 在保存记录页查看同样的五个标题文件和 images/ 本地原图。图片未保存到源文件时会明确提示。

普通“完整网页”的 HTML 加资源文件夹不能直接导入；请使用 MHTML 或 SingleFile 的单个内嵌 HTML。SingleFile 选择保存当前完整页面，不使用 ZIP、自解压或选区模式。导入副本仅留在本机 data/browser-imports/ 供重试，最终文章目录不增加原始导入文件。

读取时禁用原网页脚本、阻止联网及其他本地文件，MHTML 用 Chromium 原生解析，保留原图字节。metadata 记录导入文件校验值、来源和未使用网络；导入只能保存文件中已有的内容。

若日常浏览器也不能打开正文或验证也超时，应先解决微信访问或网络问题；导入不能替代正常验证。仍可在记录中单独点击“打开浏览器验证并继续保存”，最多等待90秒；正常验证后自动继续，关闭窗口保留可恢复提示。

首页摘要与独立保存记录页

首页只显示全库摘要及当前正在保存／等待任务，最多展示最前12个活跃条目。已完成、失效和失败记录进入 保存记录页 查看。

可按记录分类、保存状态、网站、公众号／作者、消息来源、北京时间入队日期、标题／作者／链接关键词组合筛选。支持最新、最早、最近更新及标题排序，每页20／50／100条、翻页和页码跳转。筛选条件与页码保留在地址中，可收藏并用浏览器后退恢复。

每次筛选最多查看10000条匹配结果；查询先在完整数据库中筛选，超过时显示提示。其余数据不会删除，缩小时间或其他条件可以找到默认范围之外的旧记录。原有文件查看、下载和重新保存操作均在记录卡片中。

动图与长图

长图是静态文件。生成时将GIF／WebP／APNG固定为源像素第一帧，避免逐屏截图时播放变化造成接缝不一致。MD原图和内嵌HTML仍保留原始动图字节及播放能力；metadata记录每种长图的固定帧信息。

文件内容与用途
文章标题.md可编辑正文，保留标题层级、列表、链接、上下标、代码与表格。公式保留可识别的 LaTeX；复杂表格保留 HTML。正文原图保存在 images/ 下，使用 images/001.jpg 等相对路径引用，重复图片复用同一文件。移动或备份 MD 时，请连同 images/ 一起保存。
文章标题.html公众号保留原页面；新站点保留选中正文 DOM、主要样式和内嵌原图，移除导航、推荐与评论。单独复制这一文件即可断网阅读。点击正文图片会显示原始尺寸，支持保存原图；该功能只使用 HTML 和 CSS，无需脚本。
文章标题_手机.png9:16 手机阅读窗口下排版的整篇无损长图。
文章标题_电脑.png16:9 电脑阅读窗口下排版的整篇无损长图，裁掉文章栏外的多余空白。
文章标题_metadata.json来源、作者、日期、版本、输出文件名、两种窗口参数、PNG 尺寸与校验值、逐屏覆盖与接缝检查、原图校验值、离线检查和保存提示。
images/供 Markdown 引用的原始图片文件，按 001.jpg、002.png 等编号，保留原始字节、不重新压缩。HTML 不依赖此目录。

五个顶层文件都按文章标题命名，Windows 禁止的字符会替换，过长标题会缩短以留出路径空间；完整标题始终写入 MD 与 JSON。公众号目录沿用；其他网站按网站、作者、日期、标题与短 ID 组织，避免同名文章相互覆盖。

新版恢复 images/ 作为 MD 的本地图片目录，不保存额外 HTML 副本、原图列表或辅助阅读页。MD 需与 images/ 一起携带；HTML 和 PNG 可独立复制。JSON 中的 SHA-256 用于核对四个内容文件与本地图片，JSON 自身不记录循环依赖的自校验值。

Markdown 尽量保留内容结构，字体、颜色与复杂间距请以 HTML 为准。Markdown 阅读器需要支持本地相对路径图片、内嵌 HTML 和数学公式；不支持时可用浏览器阅读对应 HTML。MD 不再写入长串 Base64 图片内容，正文更方便编辑。动态视频、音频、投票等仅保存可见静态内容，并给出提示。

离线检查

保存时阻止网络访问，验证 HTML 正文和图片；缺图或下载失败会显示“已保存 · 有提示”，并在标题命名的 metadata 文件中记录。失败图片可能保留原链接，不能算完全离线；网络恢复后可重新保存。

第二阶段：飞书消息触发自动保存

推荐先用飞书。官方长连接由本机主动连向飞书，当前电脑无需公网 IP、域名或家庭服务器。微信桌面监听依赖客户端版本和交互桌面，维护成本更高；本版本先交付飞书接入。

收件对象是你创建的飞书机器人。 给它单聊发送支持网站的文章链接即可。这个工具不会监听你与普通同事或朋友的其他会话。当前只接收纯文本和富文本中的链接；文章分享卡片、合并转发和图片消息请改发“复制链接”。

1. 创建飞书自建应用

  1. 登录 飞书开放平台开发者后台。需要有能创建并发布企业自建应用的工作区；如公司管理规则限制，需由工作区管理员处理。
  2. 创建 企业自建应用，可以命名为“文章收藏”。在应用能力中添加并启用 机器人。
  3. 在“凭证与基础信息”取得 App ID 和 App Secret。这两项直接填进本地工具页面，不必发到聊天里。
  4. 在权限管理中开通应用权限 im:message.p2p_msg:readonly（读取用户发给机器人的单聊消息）。本版本无需申请群聊全量消息、通讯录读取或发消息权限；实际后台如提示事件必需权限，请按提示补齐。
  5. 把应用可用范围设置为 自己，便于先验证。

2. 在本地工具启动连接

  1. 在本地页面打开 飞书自动保存。
  2. 填入 App ID、App Secret，勾选 启用飞书自动保存，点击 保存并应用。
  3. 等待页面显示 飞书已连接。如果失败，核对凭据、机器人能力和网络，点击 重新连接。

凭据只写入当前工具的 data/config.json，页面和状态接口不返回 Secret。文件依赖当前用户目录权限保护；不要把包含 data/ 的运行目录公开分享。再次修改设置时，Secret 留空会保留现有值。

3. 回飞书后台配置事件并发布

  1. 进入应用的 事件与回调 → 事件配置，将订阅方式设为 使用长连接接收事件。保存时本地连接必须正在运行。
  2. 添加事件 接收消息 v2.0，事件标识为 im.message.receive_v1。
  3. 进入 版本管理与发布，创建并发布版本。如需审核或安装，等待管理员处理；确认你的账号在应用可用范围内。
  4. 在飞书搜索并打开机器人“文章收藏”，以 单聊 发送一条支持网站的文章链接。
  5. 回到本地页面，连接详情应显示接收时间与链接数量；保存记录应出现来源为 飞书消息 的任务。等待五个文件保存完成。

机器人目前不自动回复消息。结果在本地页面查看；这样也不需要额外的发消息权限。若文章已经手动保存，相同链接会被去重，不会生成第二份；想完整验收可先在记录点击重新保存，或给机器人发送另一篇文章。

4. 限定发送人（可选）

第一次收件后，本地连接详情会显示发送人的 open_id。复制到“允许的发送人”并保存，即可只处理该发送人的新消息。可以用逗号分隔多个 ID。留空时接收应用可用范围内所有用户发给机器人的单聊消息，因此建议将飞书应用可用范围设为自己。

5. 运行条件

  • 电脑需要开机、联网、工具保持运行。关闭操作页面不影响后台收件；电脑睡眠时无法接收。不要依赖离线期间的所有消息都会补投，重要链接恢复后再发一次。
  • 已接收到的消息先写入本地 SQLite 队列，再异步保存；处理过程不会阻塞飞书回调。消息 ID 与文章链接分别去重。
  • 一次处理一篇文章，避免同时打开大量浏览器。程序意外退出后，已经入队但未完成的任务会在下次启动后继续处理。
  • 同一个飞书应用只运行这一份接收程序。多个长连接消费者会随机分到消息，导致某台电脑看起来漏收。
  • 本版本不修改 Windows 开机启动或睡眠设置。重启电脑后，双击“启动工具.cmd”继续运行。

先验证本地消息链路

展开 先测试本地消息处理，输入含文章链接的文字，点击“测试消息入口”。这验证消息提取、队列、保存与去重，并不能证明飞书订阅已接通；最终仍以实际发给机器人的消息验收。

常见问题

现象处理
当前运行哪个版本页面底部实时显示正在运行的版本；“保存设置”显示程序目录。也可打开 服务版本接口，核对 version 和 root。某篇保存记录的版本是生成它的版本，不代表当前服务版本。
双击新版却还是旧版页面同一端口只运行一个版本。先在旧页面停止工具，再运行新版目录的“启动工具.cmd”，最后刷新页面。启动器会拒绝复用其他版本的服务。
新格式没有作用于旧文章旧文件保留原样；点击该篇记录的“重新保存”，生成标题命名的新格式目录。
长图看起来像一条细线用记录中的手机／电脑长图阅读页，选择“100% 像素”；图片查看器整图适应窗口会把超长图缩得很小。
MD 图片或公式不显示保留 MD 同级的 images/，不要只移动 MD；阅读器需支持数学公式与内嵌 HTML；先打开对应 HTML 验证内容。MD 是可编辑源文件，显示样式由阅读器决定。
需要人工确认或缺图先确认原链接可访问；设置中开启“显示采集浏览器”，重新保存并在采集窗口完成正常验证。查看保存提示，确认原网页能正常显示图片。
页面打不开或启动失败检查端口 17880 和 logs/errors.log。其他电脑先安装 Node.js 24 LTS 与 Edge/Chrome；首次安装依赖需要联网。
飞书已连接但收不到文章核对接收消息事件、单聊权限、应用发布和可用范围。单聊发给自建机器人，并确认没有其他消费者使用同一应用。重复文章会被去重。

Mac 环境安装与软件启动

支持 macOS 14 及以上，Apple Silicon 和 Intel 64 位。先安装 macOS 版 Node.js 24 LTS，然后在 local-archive 目录运行：

chmod +x *.command scripts/mac-common.sh
bash install-mac.command
bash start-mac.command

首次安装会检测浏览器，缺失时下载匹配的 Chromium；以后双击 start-mac.command。停止使用 stop-mac.command，检查使用 doctor-mac.command。关闭浏览器或终端窗口后后台继续运行。

运行版本与升级

本次版本是 v1.3.0.p（2026-10-08），独立保存在 wx2md-local-v1.3.0.p。更新前当前电脑运行 v1.2.0.p；本次切换完成后，页面底部与 /health 应显示 v1.3.0.p 和对应目录。历史开发目录保留压缩包，文章与配置迁入当前版本。

本次已将停止后的旧版设置与任务数据库复制到新版，旧文章通过迁移后的路径继续访问，新文章默认保存到新版 archives。旧文章不会自动改写；需要更新格式时点击“重新保存”。

  1. 以后升级仍解压到 wx2md-local-v版本号 新目录。
  2. 在旧页面选择“保存设置 → 停止本地工具”；先等待正在处理的文章完成。
  3. 需要继承记录时，在旧服务停止后，把旧版 data/config.json 与 data/jobs.sqlite 复制到新版 data/；新版应尚未启动，避免覆盖新数据。保留旧归档目录，不要在数据库运行时复制。
  4. 双击新版目录的 启动工具.cmd，刷新 本地页面。查看底部版本号和“保存设置”中的程序目录。
  5. 复制的 config 可能仍指向旧 archives；在新版保存设置中改为希望保存新文章的目录。旧记录的路径不受此设置影响。

只刷新浏览器不能升级后台程序。源码 ZIP 不包含凭据、数据库或文章。本机数据迁移已完成，无需你再手工复制。

源码、维护与边界

这是以 wx2md Community v0.3.0 的 DOM 清理与 Turndown 转换逻辑为基础开发的本地版，额外增加了原网页归档、截图、队列、中文操作页面和飞书收件，并非商业浏览器插件的完整复制。

HTML 通过 SingleFile Core 保存公众号原页面或其他站点的正文阅读容器，长截图由 Playwright 浏览器直接采集，Markdown 从正文副本提取。代码、构建脚本和依赖锁文件均在工具目录。许可证与原项目署名见 LICENSE 和 THIRD_PARTY_NOTICES.txt。

pnpm install --frozen-lockfile --ignore-scripts
pnpm build
pnpm test
pnpm start

也可使用 npm 安装固定版本依赖。运行数据在 data/，归档在 archives/，日志在 logs/。本地接口只绑定 127.0.0.1，写入操作需要本机令牌，支持后续微信适配器接入；本版本尚未启用微信桌面监听。

飞书接入代码与本地模拟链路可以验证，但实际账号的应用权限、发布和消息投递需要你的飞书应用凭据才能最终验收。实际飞书投递本次未重新测试，手动保存可独立使用。
