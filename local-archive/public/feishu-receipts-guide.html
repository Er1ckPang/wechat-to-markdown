飞书真实保存结果回执指南

适用版本：v1.4.0.p，基于 v1.3.0.p；特性分支 feat/feishu-save-receipts。

开启方式

  1. 在 飞书开发者后台 打开已有自建应用，确认已启用机器人能力。
  2. 在“权限管理”申请应用权限 im:message.p2p_msg:readonly（读取用户发给机器人的单聊消息）及 im:message:send_as_bot（以应用的身份发消息）。
  3. 在“版本管理与发布”创建并发布新版本，按工作区要求完成管理员审批。已发布应用新增权限后仍须发布新版本。
  4. 在本地工具“飞书自动保存”中勾选“启用飞书自动保存”和“保存结束后回复真实结果”，保存并应用。现有凭据无需重新填写；Secret 留空保留原值。
  5. 保持电脑开机、联网和工具运行，给该机器人单聊发送公众号、知乎专栏／具体回答、CSDN、博客园或普通文章链接。文本和富文本可一次包含最多100个不同链接。

只接收授权用户发给机器人的单聊消息；文章卡片、图片和合并转发请改发复制出的链接。允许发送人设置继续生效。不补发升级前历史消息的回执。

什么时候返回，返回什么

消息先持久入队。单篇处理结束后回复原消息；一条消息含多篇时，等待该消息的全部任务结束后逐篇汇总。多篇结果较长时分段发送，标明部分编号。

回执结果 实际含义
保存完成 核对本地 MD、内嵌 HTML、手机和电脑 PNG、metadata 及已保存原图；文件大小、SHA-256、双长图完整性和 HTML 正文检查通过，未记录缺资源提示
已生成文件 · 有提示 已有输出，但存在缺图、资源未保存或其他提示；回执列出提示，不承诺完整离线
链接已失效 网站明确删除、过期或下架，或返回404／410
需要人工确认 验证码、登录或访问限制等；列出原因，迁移文章提供新链接
保存失败 采集、排版、截图或落盘等失败；列出真实原因
本地文件核验未通过 旧归档缺少可核验清单，或文件已移动、删除、改动、截图完整性未确认；不会回复“保存完成”
文章未入队 未找到支持的文章链接，或去重后超过100个链接；说明原因

回执包含核验时间、各类数量、每篇标题和链接、输出格式、原图数量及本地目录。微信链接中的临时 token 会隐藏。重复文章复用已有任务／归档，但仍为这条新消息回复，并重新核对现有文件；重复投递的同一个消息事件不再生成回执。

文件仍保存在运行工具的电脑，本功能不上传文章附件到飞书。回执中的 127.0.0.1 记录地址需在这台电脑打开，手机无法通过这个地址访问电脑文件。Markdown 移动时应带上 images/。

回执说明核验时的结果。用户随后手动删除／修改文件，或在本地对同一任务重新保存，不会修改已发送回执，也不会主动再发一次；需更新回执时，给机器人再次发送文章链接。

收到文章但没有回执

打开本地工具的“飞书自动保存”，查看“等待保存”“待发送”“已发送”和回执错误。

  • 等待保存：仍有任务未结束。长文章和批量长图需要时间，可在保存记录页查看进度。
  • 缺少权限：申请 im:message:send_as_bot 并发布应用新版本。保存文件已经落盘时无需重新抓取；点“重试未送达回执”即可。
  • 网络或限流：回执独立重试，首次约5秒，随后递增，最多间隔5分钟。发送失败不会把成功归档改成失败。
  • 开关关闭：重新启用后继续发送已有待发送回执。关闭期间的新消息仍可保存，但不建立回执。
  • 允许名单变化：已不在名单内的发送人暂停回执；恢复权限后重试。更换 App ID 后，旧应用的待发送回执不会由新应用发送。
  • 原消息删除、应用范围或机器人权限变化：按本地错误核查飞书应用和原会话。永久性失败也会保留待发送状态供排障。

回执及分段发送进度写入同一个本地 SQLite 数据库。重启继续未送达部分，已成功记录的分段不会再发；每段使用固定 UUID 和内容，降低接口重试重复消息的概率。平台幂等窗口和外部网络存在限制，不保证任意长时间故障下绝对只投递一次。

收到的消息与任务先通过同一事务写入，再返回事件处理。电脑离线时尚未收到的消息能否补投取决于飞书，不保证全部恢复；重要链接可恢复连接后再次发送。同一应用只运行一份消费者。

“先测试本地消息处理”仅测试提取和队列，不会给飞书发消息。自动测试使用自行编写的文章和模拟飞书接口，覆盖官方 SDK 请求契约、真实浏览器归档、100篇分段、文件损坏、权限失败和重启补发；真实账号投递仍需发送一条链接验收。

二次开发

feishu.mjs 接收消息；store.mjs 和 receipt-store.mjs 在入队事务中建立消息到任务的订阅；worker.mjs 通知任务结束；feishu-receipts.mjs 核验文件、冻结结果、生成分段并调用官方回复接口。回执数据库不进入 Git 或源码包。

官方参考：回复消息 API、接收消息事件、飞书 Node SDK。
